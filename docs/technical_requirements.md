
# Технічне завдання (ТЗ)

---

## 1. Загальна інформація
- **Назва проекту:** Система керування шиномонтажем.
- **Опис:**
  Веб-система для записів клієнтів, керування транспортними засобами, статистикою та сповіщеннями через email і пуш-сповіщення.

---

## 2. Основні функції

### 2.1. Користувачі
- Реєстрація та аутентифікація користувачів через Firebase.
- Зберігання токенів для Firebase Cloud Messaging (`fcmToken`).
- Управління транспортними засобами (додавання, редагування, видалення).
- Створення, перегляд та скасування записів.

### 2.2. Адміністратор
- Підтвердження та скасування записів.
- Управління прайс-листом (`Service`).
- Управління реферальною системою.
- Перегляд статистики виконаних робіт.

### 2.3. Статистика
- Підрахунок виконаних коліс у моделі `CompletedWheelCounter`.
- Перевірка загальної кількості записів за статусом (`PENDING`, `COMPLETED`, `CANCELLED`).

### 2.4. Сповіщення
- Пуш-сповіщення через Firebase Cloud Messaging:
  - **User → Admin:** Новий запит на запис.
  - **Admin → User:** Підтвердження або скасування запису.
- Email-сповіщення:
  - Нагадування про запис за день до `dateTime`.
  - Підтвердження або скасування запису.

### 2.5. Преміум-функціонал
- Знижки для преміум-користувачів (через `premiumDiscount` у `Service`).
- Генерація та перевірка реферальних кодів.

---

## 3. Архітектура бази даних

### 3.1. Моделі:
- `User`: Користувачі із преміум-статусом та реферальними кодами.
- `Vehicle`: Дані про транспортні засоби.
- `Appointment`: Записи для клієнтів із підтримкою статусів (`PENDING`, `CONFIRMED`, `CANCELLED`, `COMPLETED`).
- `Service`: Прайс-лист із розрахунками для преміум-користувачів.
- `Referral`: Відстеження реферальних зв'язків.
- `CompletedWheelCounter`: Лічильник виконаних коліс.

### 3.2. Зв'язки:
- `User` → `Vehicle`: Один до багатьох.
- `User` → `Appointment`: Один до багатьох.
- `Vehicle` → `Appointment`: Один до багатьох.

## 5. API

### 5.1. Users
- `GET /api/users`: Отримати дані про користувача.
- `PATCH /api/users`: Оновити дані (наприклад, преміум-статус або токен).

### 5.2. Vehicles
- `GET /api/vehicles`: Отримати список транспортних засобів.
- `POST /api/vehicles`: Додати новий транспортний засіб.
- `PATCH /api/vehicles`: Оновити транспортний засіб.
- `DELETE /api/vehicles`: Видалити транспортний засіб.

### 5.3. Appointments
- `GET /api/appointments`: Отримати записи.
- `POST /api/appointments`: Створити новий запис.
- `PATCH /api/appointments`: Оновити статус запису.
- `DELETE /api/appointments`: Скасувати запис.

### 5.4. Services
- `GET /api/services`: Отримати прайс-лист.
- `POST /api/services`: Додати нову послугу.
- `PATCH /api/services`: Редагувати існуючу послугу.
- `DELETE /api/services`: Видалити послугу.

### 5.5. Notifications
- `GET /api/notifications`: Отримати сповіщення користувача.
- `PATCH /api/notifications`: Позначити сповіщення як прочитане.

---

## 6. Поштові сповіщення
1. **Нагадування про запис за день:**
   - Надсилання email через Nodemailer.
2. **Підтвердження/скасування записів:**
   - Автоматичне email-сповіщення.

---

## 7. Пуш-сповіщення
- **User → Admin:** Новий запит на запис.
- **Admin → User:** Підтвердження/скасування.
